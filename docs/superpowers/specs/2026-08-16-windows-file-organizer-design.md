# 设计文档：Windows 文件整理助手（File Organizer）

- 日期：2026-08-16
- 状态：待用户审阅
- 主题：一个整理 Windows 用户文件的本地 Web 应用（扫描 → 分类 → 规划 → 预览 → 确认 → 移动）

## 1. 目标与成功标准

**目标**：帮用户把散落在各处的个人文件（图片、文档、音乐、视频等）自动归类到"大类/年份"目录；遇到应用程序文件保持不动；全程有可视化界面、先预览后执行。

**成功标准**：
1. 用户能多选扫描范围（常用用户文件区 + 整 D 盘 + 自定义目录）。
2. 扫描只读，产出可预览的"将移动到哪"清单。
3. 应用程序目录（含 .exe/.dll 等）被正确识别并保持不动。
4. 文件按"大类/年份"归入目标目录；重名不覆盖。
5. 内容识别：本地规则粗分类 + 可选 LLM 细分（可关闭）。
6. 移动可批次撤销；单文件失败不中断整批。

## 2. 已确认的决策

| # | 决策点 | 结论 |
| --- | --- | --- |
| 1 | 整理语义 | 干跑预览 → 用户勾选确认 → 才真正移动 |
| 2 | 扫描范围 | 默认：常用用户文件区 + 整个 D 盘；GUI 提供多选 + 自定义目录 |
| 3 | 目标结构 | `归档根/大类/年份/`（如 `整理归档/图片/2026/`） |
| 4 | 内容识别 | 本地规则先行 + 可选 LLM 细分（DeepSeek），设置里可开关 |
| 5 | 技术栈 | 前后端分离：Node/TS 后端 API + React/Vite SPA |

## 3. 架构

pnpm workspace 单仓，两个子包：

- `server`：Node.js + TypeScript 后端，监听 `127.0.0.1`，REST + SSE，内置 SQLite。
- `web`：React + Vite SPA；生产由后端托管构建产物，开发用 Vite 代理。

后端 7 个模块（单一职责、通过数据对象接口交互、不 import 彼此内部实现）：

| 模块 | 职责 |
| --- | --- |
| `scanner` | 递归遍历扫描根，跳过系统/应用目录，采集元数据，增量扫描 + 可取消 |
| `classifier` | ①本地规则（扩展名 + magic bytes + 元数据）②可选 LLM 细分 |
| `planner` | 计算目标路径（大类/年份）、重名冲突决策，产出 from→to 计划行 |
| `executor` | 干跑预览 → 按批次移动；同卷 rename / 跨卷 copy+校验+删；写移动日志供撤销 |
| `catalog` | SQLite：文件索引、扫描记录、分类标签、移动批次、撤销日志 |
| `api` | REST 端点 + SSE 进度通道，统一错误结构 |
| `config` | 设置持久化：扫描根、归档根、排除列表、LLM 开关、API key |

前端 4 个页面：扫描页（多选 + 自定义目录 + 进度）、预览页（缩略图 + 分类徽章 + from→to + 勾选筛选）、执行页（进度 + 结果 + 撤销）、设置页（LLM 开关/额度、归档根、排除规则）。

## 4. 数据流

```
选根目录 → 扫描 → 分类 → 规划 → 预览 → 确认执行 → 结果/撤销
```

1. **扫描**：scanner 递归遍历，跳过系统/应用目录，元数据 upsert 进 catalog；进度 SSE。全程只读。
2. **分类**：第①级本地粗分类；"拿不准"的文件若 LLM 开启，第②级 DeepSeek 出内容标签，回写 catalog。
3. **规划**：planner 逐文件算 `归档根/大类/年份/`，做冲突决策，产出计划行 `{from, to, reason, category}`，只存内存/临时表，不碰文件。
4. **预览**：预览页渲染计划行，用户筛选/取消勾选。
5. **确认执行**：executor 开批次，先写日志再动文件，逐文件执行，状态 SSE 回传。
6. **结果/撤销**：汇总成功/失败/跳过；支持按批次撤销（日志逆序回搬）。

**不变量**：第 1~4 步绝不修改文件；只有 executor 拥有写文件权限，且是唯一写文件模块。

## 5. 安全与冲突

### 5.1 "应用程序文件保持不动"判定（skip 规则）

1. **硬跳过**：`Windows`、`Program Files`、`Program Files (x86)`、`ProgramData`、`AppData`、`$Recycle.Bin`、`System Volume Information`、`node_modules`、`.git`，及所有隐藏/系统属性目录。
2. **应用目录启发式**：目录含 `.exe`/`.dll`/`.msi`/`.appx` 等可执行，且用户媒体文件占比低 → 整体跳过。
3. **排除列表**：用户可在设置里额外排除任意路径；预览里可对单个目录标"跳过"。

> D 盘整盘扫描同样套用以上规则，故 D 盘下的开发工具/软件目录一样被跳过。

### 5.2 移动安全

- 归档根默认 `<卷根>/整理归档/`（可改）。
- 同卷 rename（瞬时）；跨卷 copy → 校验 → 删源（失败保留源）。
- 重名冲突：比大小+哈希；相同 → 跳过（标记"已存在"）；不同 → 追加 ` (1)`、` (2)`，不覆盖。

### 5.3 撤销

- 批次存完整移动日志（源→目标）；撤销 = 逆序回搬，仅在日志仍在且目标未被二次改动时可用。

## 6. 错误处理

| 场景 | 处理 |
| --- | --- |
| 目录无权限 | 记录"跳过 + 原因"，继续 |
| 超长路径（>260） | `\\?\` 前缀访问 |
| 文件占用/锁定 | 标"重试"，批次末尾重试一次，仍失败标"失败+原因" |
| 跨卷复制失败 | 先校验再删源；失败保留源，标失败 |
| LLM 失败/超时/限流 | 回退本地粗分类，标"未细分"，不阻塞 |
| API 异常 | 统一 `{code, message, detail}`，前端 toast + 重试 |
| 用户取消 | 扫描/执行支持中止；已完成原子操作不回滚 |

## 7. 测试策略

| 层 | 内容 |
| --- | --- |
| 单元 | classifier 规则、planner 路径与冲突、撤销日志逆序 |
| 集成 | scanner+classifier+planner 在临时 fixture 上跑通（含假 Program Files/应用目录/重名文件）；executor 干跑 + 真移动全流程 |
| 前端 | 预览勾选/筛选、API 客户端（mock 后端） |
| 安全回归 | scanner 永不进入 skip 列表；executor 干跑零写 |

测试一律用临时目录 fixture，永不触碰真实用户文件；跨卷策略用单元测试验证决策逻辑。

## 9. 假设与边界

- **单用户本机使用**，不设计多用户/鉴权/远程访问（监听 127.0.0.1）。
- 归档目标与源在不同卷时的跨卷复制是慢操作，UI 需展示进度。
- LLM 提供商默认 DeepSeek（复用用户已有 API key 或单独配置）。
- 第一阶段不实现：文件去重（除重名跳过外）、实时文件监控、多语言 i18n。
